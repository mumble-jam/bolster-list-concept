Address field

A site's address, looked up as you type, its parts kept apart so it can be mapped, routed and sorted by area (D139). The street line is a combobox: pick a suggestion and the parts below fill, each still editable, and the cursor moves on to the unit, which no lookup knows. Without a lookup service it's the same fields, typed by hand. The country decides the parts' words, the state or province list and the postal code's check.

With a lookup

Try “barton”, “orchard” or “toronto”. A Canadian pick switches the country, and with it Province and Postal code. Nothing found keeps what you typed: fill the rest by hand.

Without a lookup

The same fields, typed by hand: what a product gets before it adds a lookup service, or if it never does. Nothing to wire; the formats and checks still hold.

Other countries

Canada: Province from its list, Postal code checked and spaced (K1A 0B1). Elsewhere: Region, optional and typed, and the postal code as written. Change the country to see the parts change.

Rules

  • An address is kept in parts: street, unit, city, region, postal code, country. Lists and records read it on one line (D59).
  • The street line looks the address up as you type; a pick fills the parts, each still editable. A lookup is an aid, never a gate: what's typed always stands.
  • Without a lookup service, the same fields typed by hand. A product can leave the lookup out and add it later without changing the form.
  • The country decides the words (State and ZIP code, Province and Postal code, Region and Postal code), the list and the check. It starts as the company's.
  • The rows follow F-rows: the street beside a short unit, the city beside the state and the code, the country alone and full width. Phones stack them.
