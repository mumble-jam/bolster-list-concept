Page types

To-be documentation

This page shows every kind of page in Bolster's live product today (as-is), drawn as a schematic, with the interactions that define it. It's one part of the audit; the as-is board holds the rest: tokens, components, layouts, patterns and drift. Numbered pins on each schematic match the list under it. The screenshots under each type come from the layout audit, taken at 1440, 768 and 500 px wide. The 500 px captures stand in for 375, since both fall in the same breakpoint tier. Where a type has no screenshot, its structure comes from a read-only DOM read on 3 October 2026. Nothing in Bolster was edited, submitted or created to make this page. Interactions marked "not opened" were left alone because they change data or preferences.

Frame · every company page

App shell

The frame every company page sits in: a black top bar, a black icon rail, a warm section sidebar for the current area (Jobs, Financial, Settings…), and a sticky page title bar. Below 768 px the rail and sidebar give way to a hamburger and a black bottom tab bar.

Core interactions

  1. Rail expands on hover from 60 to about 245 px, over the content, with labels. "Pin sidebar" keeps it open (not opened: it's a preference).
  2. Section sidebar lists the pages of the current area. On phones it's behind a hamburger.
  3. Company switcher opens a menu: Switch company, Company settings.
  4. Global search is a button styled as a field. It opens a full-screen blurred layer with type chips (Client, Invoice, Job…).
  5. Avatar menu: Edit profile, Manage users, Logout. Help, the assistant and product updates sit next to it.
  6. Page title bar: Space Grotesk title, a refresh icon, page actions on the right. Sticky.
  7. Bottom tab bar on phones: Getting started, Dashboard, Jobs, Customers, More.

As-is issues

  • Rail buttons have no accessible names; the tooltip is the only label.
  • At 768 the sidebar stays open and squeezes the page (settings labels wrap to three lines).
  • On phones the sticky title covers the first heading on three pages.
  • The rail widens over 1 s, which feels slow.

Overview

Home and onboarding

A centred single column with no section sidebar. A hero with an illustration and an assistant prompt sits above a checklist of setup tasks. Each card starts a short guided flow.

~/getting_started · ~/home · ~/getting-started · ~/onboarding/welcome

Core interactions

  1. Assistant prompt ("Draft an estimate for…") hands off to Bolster's assistant. Not opened.
  2. Checklist cards: the whole card is a button that opens a guided flow; a check shows it's done.

As-is issues

  • Task cards are 74 px buttons with no focus style.
  • The checklist can be hidden from settings ("Show Getting started"), so the home page is optional.

Overview

Dashboard

A grid of white widgets on the page background, two columns on desktop and one below 768. Filters in the title bar scope every widget. Widgets are summaries that link into lists: recommended actions, pipeline stages, assignments, money.

~/dashboard · ~/sales-dashboard · ~/jobs-dashboard · ~/metrics · ~/marketing · ~/financial-services/financial-overview

Core interactions

  1. Scope filters ("Everyone", "All groups") are tertiary buttons with a chevron. They open the select sheet from the bottom right. Opened.
  2. Customize changes which widgets show. Not opened (preference).
  3. Create (+), black, icon only. Not opened.
  4. Recommended-action rows (Draft pending jobs to send, Unapproved change orders…) each with a coloured dot, a count and a chevron; they open the matching list.
  5. Pipeline accordion: one row per stage with a coloured left edge and totals.
  6. Widget handle (⋮⋮) in each widget header; on the financial overview the same widgets carry "Move" handles for drag reordering.

Variants

  • Sales and jobs dashboards: same frame, different widgets.
  • Financial overview: customisable widgets (Payment account, Cashflow summary, Money overview, Payables, Accounts, Payment volume, QuickBooks) with drag handles and "Customize". DOM read only.

As-is issues

  • Three hover greys across row-style clickables; accordion rows use Tailwind's cool #e5e7eb border.
  • Widgets have no border, only white on the page; the layout depends on the canvas being darker.

Overview

Report builder

Pick a report, set its filters, then generate it. The whole page is a filter bar until a report is generated.

~/reports/:id?

Core interactions

  1. Choose report: a select for the report type.
  2. Filters: All owners, All jobs, Status, Last 30 days. Same tertiary-button selects as the dashboard.
  3. Generate builds the report. Not pressed, so the output wasn't seen.
  4. Report output: not captured.

As-is issues

  • Lives in the Financial area's sidebar.
  • Output, empty and loading states are a gap.

No screenshot yet: Reports was added to the audit after phase 3.

Collections

Data list

The workhorse: title and toolbar, a row of filter cards that work like tabs, then a virtual-scrolling grid of rows. Rows are selected with one click and opened with two. It's the most common type in the app.

~/estimates (quotes, proposals, pending) · ~/jobs → ~/projects · ~/clients · ~/leads · ~/invoices · ~/items · ~/vendors · ~/rfqs · ~/expenses · ~/vendor_orders · ~/users

Core interactions

  1. Table search ("Search this table…", 48 px). One of four search designs in the app.
  2. Filters and columns: an icon-only button whose only name is a tooltip. It opens a centred dialog with Filters / Columns tabs and a footer: "Reset all", "Apply · n". Opened.
  3. Create (+), black, icon only. Not opened.
  4. Filter cards act as tabs: one is selected (blue fill with a notch) and each shows a count and a total. They scroll sideways.
  5. Single click selects a row: grey fill, checked box, and a black bulk bar replaces the column header ("1 selected", Edit, Send now, Sign & book, Archive, More). Opened.
  6. Double click opens the job workspace over the list and puts ?job=<id> in the URL. Opened.

Variants

  • With filter cards: estimates, jobs, clients, leads (Fresh, Stale, Abandoned; 56 px cards).
  • Plain: users and other settings lists. Search plus "Create new", no cards.
  • Catalog sheet: items. Sheet / Gallery view switch, inline-editable cells and a save bar ("No changes to save"). DOM read only.

As-is issues

  • Rows are divs: no focus, no keyboard selection, and double-click is the only way to open.
  • Filter cards are buttons with no tab semantics or focus style.
  • At 768 every column but name, status and amount disappears.

Collections

Board

The pipeline as a kanban. Each stage is a column with a coloured top rule, a total and a value, then stacked cards grouped by sub-status. On phones the board becomes a vertical list of stages.

~/pipeline

Core interactions

  1. Stage columns scroll sideways: 6 visible at 1440, about 2.5 at 768.
  2. Job cards grouped under a sub-status ("Drafts", "Never sent"). Opening one wasn't tried; dragging between stages wasn't tried either (it would change a job's stage).
  3. Empty stage explains itself and offers actions ("Add lead", "Lead form"). Not opened.
  4. "See all …" at the foot of each column goes to the filtered list.
  5. Group filter ("All groups") opens the select sheet, as on the dashboard. Table search and the filter icon sit next to it.

As-is issues

  • The pipeline's section nav sits inside the main column, not in the shell's sidebar.
  • Stage colours are the only signal of stage order.

Task list

Tasks grouped by date or by job, under a row of stat tiles. Each row carries inline cells for date, priority and assignee, so the list is also where tasks get edited.

~/schedule · ~/my-tasks (same view) · ~/vendor/task-list

Core interactions

  1. Date / Job switch: a segmented control that regroups the list. Not opened.
  2. Stat tiles: Overdue, Due today, Leads, Proposals; counts only.
  3. Collapsible groups ("Overdue 0/3", "No due date 0/43") with add (+) and more (⋯) per group.
  4. Inline cells: due date chip, "Set priority", and a dashed assignee circle. Each writes on click, so none was opened.
  5. Select turns on multi-select; Filter and "Create task" sit next to it. Not opened.

As-is issues

  • At 768 task names truncate to a few letters ("New t").
  • Inline cells are 13 px text buttons in light grey (#9e979b) with no focus style.
  • Schedule and My tasks render the same view under two names.

Records

Job workspace

A whole application inside a dialog. It opens over the list it came from, with its own header, its own section nav and an editable estimate spreadsheet. It's where a job is built, priced and sent.

any list + ?job=<id> · related record editors: ~/estimate/:id · ~/assembly/:id · ~/invoice/:id · ~/vendor/:id · ~/user/:id

Core interactions

  1. Opens over the list on double click and writes ?job=<id> to the URL. The app re-adds it on every route change until the dialog is closed.
  2. Own section nav: Overview; Pre-production (Estimate, Takeoff, Proposal presentation, Selections); Production; Documents; Messages; Settings. Count badges, and a yellow "Job notes" button at the foot.
  3. Preview and send: a yellow split button, the one forward step for the job. Not opened.
  4. List / Sheet / Cards: a segmented view switch for the estimate.
  5. Live spreadsheet: cells edit in place and save as you go; a cell is focused on open. Never typed into or blurred.
  6. Close (×), top right, with no accessible name.

As-is issues

  • It's a page built as a modal: no back button, the URL trick, nested navigation.
  • The most local variation in the audit: 18 text colours, 38 backgrounds, 15 radii, 28 type styles.
  • The stand-alone record editors (invoice, assembly, vendor) weren't opened; whether they share this frame is a gap.

Records · client-facing

Document preview

What the client sees: a proposal or invoice as a long centred document with a cover image, a summary card and sections. A sticky action bar carries the decision. The same layout serves the public links clients open.

~/estimate/preview/:id · ~/estimate/presentation/:id · ~/invoice_presentation/:id · ~/presentation/:id · /pub/presentation/:id · /pub/invoice/:id

Core interactions

  1. Sticky action bar: Decline proposal, a note ("Your own copy, approving is off"), Next choice, Approve, and the estimated price.
  2. Next choice steps the client through optional upgrades ("1/1 options").
  3. Approve: the client's decision. Never pressed.
  4. "Preparing your estimate…" overlay for 10–20 s before the document renders.
  5. On phones the bottom tab bar sits on top of the action bar and hides Approve and Next choice.

As-is issues

  • At 768 the action bar text overlaps ("Decline proposal" runs into the next label).
  • The only place blue is used for primary actions (Approve, Next choice).
  • The public versions (/pub) weren't opened; they're assumed to share this layout without the shell.

Communication

Messaging

A channel list beside the open conversation, one channel per job or contact, with a details pane at wider sizes. With no channel open, the right side is an empty state.

~/messages · ~/client-messages · ~/vendor-messages · job workspace → Messages

Core interactions

  1. Channel list with search and a filter button. Each row has an avatar, the job or contact, the last activity and a date.
  2. New channel (+), yellow. Not opened.
  3. Conversation pane: "No channel selected" until a channel is opened. Opening one wasn't tried (it can mark messages read).

As-is issues

  • At 768 the third pane squeezes to about 56 px and its empty state wraps word by word.
  • On phones the page title and search scroll under the top bar.

Configuration

Settings hub

A two-column grid of cards. Each card holds a group of link rows that open a settings form or list. The settings sidebar repeats the same groups.

~/settings · ~/settings-dashboard · ~/integrations (gallery variant)

Core interactions

  1. Grouped sidebar: General, Assets, Financial, Team, Integrations, Your settings, Import tools. The groups collapse.
  2. Link rows: icon, title, description, chevron; they open a form or list.
  3. Integrations card; the integrations page itself is a gallery of cards (AutoCost, Home Depot, Lowe's, CompanyCam, ABC Supply, Hover, QuickBooks, Calendar sync, Webhooks).

As-is issues

  • Link rows are <div role=button>, not links, and have no focus style.
  • Hub and sidebar list the same destinations in different orders.

Configuration

Settings form

Sections of label-left, field-right rows. A single "Save changes" in the title bar is disabled until something changes.

~/company · ~/estimating_defaults · ~/estimation-settings · ~/taxes · ~/payment-settings · ~/schedule-settings · ~/presentation-themes · ~/user/:id

Core interactions

  1. Save changes: one page-level save, disabled until something is edited. No autosave here, unlike the workspace.
  2. Text fields (48 px). Never typed into.
  3. On / Off as a segmented control rather than a toggle.
  4. Selects (40 px) open the bottom-right select sheet. Opened ("Company type").
  5. On phones the sticky title covers the first section heading.

As-is issues

  • 48 px fields next to 40 px selects in one form.
  • Two fields display the literal text "null".
  • At 768 the sidebar stays and labels wrap to three lines.

Mobile-first apps

Field and estimator apps

Separate phone-first apps for crews and estimators, with their own bottom nav and large touch actions. On desktop they run inside a "Bolster Field simulator" frame with a Phone / Tablet / Full width switch.

/app/field/* (home, today, jobs, job details, logs, tasks, schedule, chat) · /app/estimator/* (estimates, items, options, preview, send, paywall)

Core interactions

  1. Simulator switch: Phone / Tablet / Full width, desktop only.
  2. Today card: date, "Nothing scheduled", and a link into today's jobs.
  3. Clock in: a black 56 px hero action with yellow text. Never pressed.
  4. Own bottom nav for field pages.

As-is issues

  • Leaving the field app for company pages raised a "private object" error toast (seen twice, after scripted navigation).
  • The estimator app wasn't opened; it's listed from the routes only.
