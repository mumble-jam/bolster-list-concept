Iconography

Font Awesome 6 Pro, Regular in the page and Light in the app shell's chrome. Icons are meaning, so the system owns them: one meaning, one icon, everywhere, and every icon without a label has a tooltip.

Stablemodel/icons.jsonspecimens/icons.htmlconcepts/shared/icons.jsconcepts/shared/shell.jsUpdated 2026-11-05

The set

Bolster's icons are Font Awesome 6 Pro, the set the product already uses (D23). The system's CSS doesn't depend on it: components size whatever svg they hold, so another set could be swapped in without touching a component.

Two of Font Awesome's weights are used, and where an icon sits decides which. A page never picks a weight itself.

WhereWeightWhy
In the page: headers, toolbars, tables, cards, menus, dialogs, the recordRegularOne weight for everything in the page, on any surface, so icons next to each other match (D84)
The app shell's chrome: the top bar and its menus, the fold button, the floating menu buttonLightAs in the product's chrome (D23, D84)
The dark menu: the sidebar, the rail, the folded menu's popup, the phone's menuRegularA weight up from the rest of the chrome; trying out (D93)
Search and helpRegular, everywhereAs in the product

This is built so it can't be missed: every icon's key draws Regular, and the shell alone draws the Light copies, named l-<key>. Whatever a page draws is Regular.

One meaning, one icon

Icons are meaning, so they belong to the system, not to a page (D58). The vocabulary in system/model/icons.json maps each meaning to one icon, and the same meaning gets the same icon everywhere: a date is always the calendar, a link to a job always the briefcase, Archive always the box.

  • A field takes its icon from what its key means, else from the record it links to, else from its type. A vendor order's Vendor is a store because of its key; a Client column is people because it links to a client; a Due date is a calendar because it's a date.
  • An action takes its icon from its whole label, else from its verb. “Download proposal (PDF)” is listed by label; “Edit job” and “Edit estimate” both take Edit's pen from the verb.
  • “Change <field>” takes that field's icon: Change status the status mark, Change owner the person.
  • A meaning the vocabulary doesn't cover stops a built page until an icon is proposed and approved. There are no stand-in icons, and an unknown action never borrows Edit's pencil.

The vocabulary as it stands, drawn from icons.json. Picks marked proposed joined for vendor orders, tasks, the pipeline and bid requests, and are waiting for the product designer's review. The icon vocabulary specimen reads the file live and shows how every field and action on the built vendor orders page gets its icon.

Matching side by side

Font Awesome draws every glyph on the same square, but not at the same size inside it: an × fills about 62% of the square, a circle or the expand arrows all of it. Sized by the box, two icons next to each other look mismatched. So icons that sit together match in ink and line, not in box size (D41).

  • Match the ink. Icons in one row or container, under 24px apart, draw about the same amount of ink, within 15%. A glyph that's smaller or bigger than its neighbours is drawn at its own size: ic(name, size, { optical: true }) sets its --icon-size, whatever the control's icon box.
  • Match the line. An icon drawn smaller goes one weight up, so its lines stay as thick as its neighbours', within 0.25px.
  • Solid marks, such as the ⋯ dots, have no line to match and count a quarter bigger: a filled shape reads heavier than an outline.

In the record's header, expand is drawn at 12 and close at 18, so the two read the same size. An × beside fuller icons can't match both ways; it's matched by ink, and its line may differ a little. scripts/check-icons.js measures this in the browser (__icons()) and lists the groups that don't match, and any Light icon outside the shell's chrome.

Usage

  • Leave an icon out unless it helps people find or tell apart. A label is clearer than any icon.
  • An icon's colour follows its text: secondary beside secondary text, the danger colour on a destructive menu item.
  • The app's menu has two known overlaps still to settle: it draws Subs and vendors as a truck where the vocabulary's vendor is a store, and Customers and Groups share the people icon.

Accessibility

  • Every icon without a label has a tooltip (D52), whether it's interactive (an icon button) or descriptive (a kind's icon in a table cell). A lone symbol (×, +, ⋯) counts as an icon.
  • Put data-tip="…" on the icon or its control; system/components/tooltip.js draws it in the top layer, so no card or table clips it. It shows only while the element's own label isn't showing, so a control that folds to an icon on a phone gets one and the full control doesn't repeat itself.
  • The control keeps its name in aria-label, with the same words as the tooltip; the tooltip itself is hidden from screen readers, and the icon's svg is aria-hidden.
  • The rail is the one exception: it opens on hover and focus and shows every label.
  • scripts/check-tips.js (__tips()) lists every visible icon without a tooltip. Run it at desktop and phone width, with the menus, the record and the bulk bar open, since controls lose their labels on phones.

Code

In markup, an icon is a placeholder the page swaps for the drawn icon when it loads. In a script, ic() returns the svg.

<button class="button" data-variant="ghost" data-size="sm" data-icon-only
        aria-label="Refresh" data-tip="Refresh">
  <i data-icon="refresh-cw"></i>
</button>

// in a script: the key, its height in px, and whether it keeps its own size
ic("xmark", 18, { optical: true })

Adding an icon

  1. Check the vocabulary first. If the meaning has an icon, use it. A new meaning gets a proposed icon, which joins system/model/icons.json once the product designer approves it.
  2. Pick it on fontawesome.com, from Font Awesome 6 Pro.
  3. Add it to the map, scripts/fa-icon-map.mjs: the system's key, then Font Awesome's name for it.
  4. Fetch and build: the fetch needs a licensed Font Awesome token, kept outside the repository. 
    node scripts/fetch-fa-icons.mjs ~/fa-pro/icons.json && node scripts/build-icons.mjs ~/fa-pro/icons.json
  5. Don't edit the subset by hand. concepts/shared/icons.js is generated with the Regular and Light copies of every key; on a branch, merge the map and build it again.

Licensing

Font Awesome 6 Pro is licensed to Bolster. The icon subset can be used in Bolster's own projects, but nothing published outside them may carry it, and no token or package belongs in the repository.
