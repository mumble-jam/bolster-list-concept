Bulk actions

Acting on several rows at once: checkboxes only where a list has bulk actions, a floating bar that counts and acts, three slots then More on desktop, and a select mode on phones.

Stablecomponents/floating-bar.csspatterns/list-page.cssUpdated 2026-11-02

Where a list has actions that make sense for several rows at once, its rows can be ticked, and a bar floats up over the list with the count and those actions. Where it has none, there's nothing to tick: no checkbox column, no Select button, no long press (D48).

Selecting

  • The checkbox in a row's first cell ticks it. A checkbox click never opens the row.
  • The header's checkbox selects all, and shows mixed while only some are ticked.
  • Shift-click ticks a range. It's in the contract (I6) and not yet built in the list concept.
  • Select all on the bar reaches past the rows on screen to everything that matches the filters: “Select all 132”.
  • Escape clears the selection from anywhere on the page, unless a menu, a dialog or a text field takes it first.

The bar

  1. The count. A chip that holds its own ×: a click clears the selection. With everything ticked it says “All 132 selected”.
  2. Select all. A quiet underlined link, gone once everything is ticked: the chip's × already clears it all (D54).
  3. Actions. The list's first actions, in the order it declares them, most important first, each with its icon beside its label. A menu (Change status) is one slot.
  4. More. The rest, Delete last after a rule, in red.

The bar is the chrome's dark capsule, 48 tall with 6 around its buttons, its corners concentric with theirs. It floats at the bottom of the list, slides up 8px and fades in over 240ms, and leaves the way it came; with reduced motion it only fades. While the record is open beside the list, the bar centres on the list, clear of the record.

Three slots, then More

A bar that holds every action turns into a toolbar. So the bar has a fixed number of slots, and the rest goes into More (D36):

WidthSlots
1100 and upThree, then More.
768 to 1099Two, then More. The labels stay.
Below 768Up to two actions, More, then Delete, in the bottom bar's four places (below).
  • More never holds just one action. If only one would be left over, the last slot goes into More with it.
  • Delete lives in More, last, after a rule. It comes out onto the bar, after its own rule, only when every action fits without a More (several jobs: Change status, Archive, Delete).
  • So after the count and Select all, the bar has at most four buttons.

On phones

Phones have no checkbox column. Selecting is a mode:

  • Starting it. Select in the page header, or a long press on a row (450ms, a tick of vibration where there is one), which starts the mode with that row ticked. Moving the finger first cancels the press, so a scroll never selects.
  • In the mode, the checkboxes slide in and a tap ticks a row instead of opening it. The header's title gives way to the count (“Select jobs” before anything is ticked), with Select all and Done at its end.
  • The count stays in reach. Once the page header has scrolled away, a compact bar with the same three (the count, Select all, Done) takes the top of the screen, in the chrome's dark. It follows the bars as you scroll, and ticking a row brings it back at once (D39).
  • The action bar takes the bottom of the screen, in the chrome's own dark: icons over labels, up to two actions, More, then Delete in red. When a label wouldn't fit its place, the bar takes one action fewer and that one goes into More, so the rest widen. Until something is ticked its actions are disabled. The floating menu button and Create step aside for it.
  • Done ends the mode and unticks everything.

Usage

  • Give a list checkboxes only when it has a bulk action. A checkbox that leads nowhere is a promise the page doesn't keep.
  • Delete confirms, from the bar as anywhere else; so does Archive, which can be undone (see Confirm or undo).
  • The bar says what's ticked, not what's on screen: after Select all, the count is every matching row.

Accessibility

  • The bar is a role="toolbar" named with the count: “Bulk actions for 3 selected”. The count's words are a polite live region, so a screen reader hears the selection change.
  • The count chip is a button named “Clear selection (3 selected)”.
  • Tab reaches each row's checkbox and link; Space toggles the checkbox.
  • After Select all, focus moves to the count chip, since the link it was on is gone (D54).

What it replaces

  • A bar with a trailing × to clear the selection, beside a count that couldn't.
  • A bar that showed every action from 1100 wide (one booked job: Edit, Invoice this project, Review customer, Download and More).
  • “Unselect all” beside a chip whose × already did the same.
  • Checkbox columns on lists with no bulk actions.
