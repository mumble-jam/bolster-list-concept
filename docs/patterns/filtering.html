Filtering and search

How a page narrows what it shows: summary cards as work queues, Add filter for the rest, a chip for each filter that's set, search that says what it looks in, and a date range on the main date.

Stablecomponents/toolbar.csscomponents/chip.csscomponents/summary-cards.cssconcepts/shared/shell.jsUpdated 2026-11-02

A page narrows what it shows with a few parts that work the same everywhere: summary cards for the slices people act on, Add filter for everything else, a chip for each filter that's set, a search field, and a date range where the page has a date. What's set always shows, as a chip, so nobody is left wondering why a list looks short.

The parts

PartWhat it's forRule
Summary cardsThe work queues: a status a task acts on, or a slice another task works on (Missing documents).Four at most after All; one at a time (D66).
Add filterEvery other filter the page offers, in a menu.The toolbar shows Add filter and the filters that are set, never empty ones (D45).
ChipsOne per filter that's set, its name and values.A click changes it, × removes it, Clear all removes every one.
SearchFinding a row by its words.Says what it looks in (D46).
Date rangeThe page's main date.Offered on any list with a date column (D46); see Picking dates.

Summary cards are work queues

A card is named by the task it serves (Unpaid, Not sent, Missing documents), shows money where the key figure is money with the count beside it, and filters the list below. Pressing a card applies its filter; pressing another replaces it; pressing it again, or All, clears it. Its chip reads as the card (“Missing documents”, not “3 selected”). A filter the page opens with, such as Active vendors, is the default view, never a card. See Summary cards.

Add filter and chips

  • Add filter's menu lists the filters not set yet, each with its icon. The pinned ones, at most three (usually status, owner and a date), come first; the rest follow in the page's order. Once there's nothing left to add, Add filter is disabled.
  • Picking a filter opens its options, a picker under its chip. Options apply as they're ticked, each with how many rows it would show.
  • A chip holds the filter's name and its values (“Status: Pending, Booked”). A click reopens its picker; the picker stays on its chip while the chips are drawn again.
  • × and Clear all remove, at once, with no confirmation. Focus goes back to Add filter, unless the page names a better place (on the timeline, the next chip).
  • The count leads the row: “64 of 132 jobs”. It stands a chip tall, so the row opens once and doesn't grow again when the chip comes.

The chips, Clear all, Add filter's menu and where focus goes are the shell's, written once (BolsterShell.filterChips, D126); a page passes what removing a filter and clearing them all do. Tasks, the pipeline and the timeline use all of it; the lists use the chip, Clear all and the menu, and also show a filter added but not set, and a search, as chips.

On a page without a card

Where the toolbar sits on the page rather than in a table card (Tasks, the pipeline, the timeline), Add filter is an icon button, then a rule and the count, and the search is a button at the end that opens into a field. The chips sit on a row under the toolbar. On the timeline everything that narrows it is under the one filter button: its menu has Show first (finished jobs, links between stages, ticked at once), then Filter by, Jobs first. What's hidden is a chip too (“Hiding”), so Clear all brings everything back (D127).

Search

  • In a table card, search is a bare field beside Add filter, edged when hovered or focused. Its accessible name and its hint say what it looks in: “Search by client, job or address”.
  • On a page's toolbar, search is a button that grows leftwards into a field. It closes again when left empty; Escape empties and closes it.
  • Escape in a search field with words in it empties it first.
  • Search and the filters narrow together: a search with filters set looks only in what they leave, and the empty state names both.

Grouping

Grouping isn't a filter, but it sits with them in Display settings. A list is grouped only where people need it, by its status, a person or a category by default, or by a column whose values repeat across many rows (a customer, a city, a trade). Never by what differs on nearly every row: names, numbers, amounts, exact dates. Without grouping, Display settings has no Group by (D47).

What a page opens with

A page opens unfiltered unless the source page has a reason to start narrower, and then that's its default view, with All a tap away. Tasks open with no filter set, every kind of task shown and no chips (D108). The timeline keeps the filters people set in the browser, so it opens as it was left.

At each width

WidthWhat changes
768 and upAs above. The toolbar sticks under the top bar as the list scrolls.
Below 768Add filter is an icon button with no edge, beside display settings. The date range shows only its value and gives way before the search field. The chips row scrolls sideways rather than wrapping, fading at the edge where there's more. Summary cards scroll sideways, the insight card first. Every picker is a bottom sheet.

Live areas keep their shape

Filtering changes values, never the layout around them: the count changes, columns keep their widths (measured over the whole list, not the rows on screen), and nothing that the person isn't pointing at moves. A filter that leaves nothing shows the empty state in the table's place, with Clear all filters. Two breaks of this are still open in the list concept: the first chip pushes the table down, and filtering to nothing collapses the table under the pointer. See Focus and keyboard (I13).

Keyboard

  • Add filter and each chip open their picker with Enter or Space; arrows move in its menu, Escape closes it and returns focus to the button that opened it.
  • A chip's × is its own button, named “Remove status filter”.
  • Summary cards are toggle buttons (aria-pressed), each a tab stop.
  • A picker opened from a chip that's then removed (its last value unticked) stays where it is, and Add filter says it's open.

What it replaces

  • Empty chips for unset filters in the toolbar (“+ Owner”, “+ City”), before anything was filtered.
  • Filter cards that were plain buttons with no selected state, and cards made from whichever statuses a task named (an Active card holding most of the list).
  • Copies of the chip and Add filter code on each page, which had drifted apart (D126).

Code

<div class="list-chips">
  <p class="result-count"><strong>64</strong> of 132 jobs</p>
  <div class="filters" id="filters">
    <span class="chip" data-active>
      <button type="button" class="chip-main" aria-haspopup="dialog" aria-expanded="false"><span class="chip-field">Status:</span><span class="chip-value">Pending, Booked</span></button>
      <button type="button" class="chip-remove" aria-label="Remove status filter" data-tip="Remove filter">…</button>
    </span>
    <button type="button" class="button" data-variant="ghost" data-size="sm">Clear all</button>
  </div>
</div>

// the shell draws the chips and Clear all, and puts focus back
const chips = BolsterShell.filterChips({ onRemove: (key) => unset(key), onClear: () => unsetAll() });
chips.render([{ key: "status", label: "Status", text: "Pending, Booked" }]);
