Checkbox, radio, toggle

The browser's own inputs, restyled: keyboard, forms and screen readers work with no script. One “on” colour for every box and dot, and the label is the hit area.

Stablecomponents/choice.cssUpdated 2026-11-02

When to use

  • Checkbox for a yes or no that's saved with a form, and for picking several from a list (a filter's statuses).
  • Radio for one of two to five options people should see side by side. More than that, or options that don't need comparing: a native select (Field).
  • Toggle for a setting that applies the moment it's flipped. If the change waits for a Save button, use a checkbox.
  • Segmented control, not radios, to switch a view or a mode in place (Segmented control).

In a list, rows have checkboxes only where there are bulk actions to run on them (D48). A list without bulk actions has no checkbox column, and on phones no Select button and no long press (Bulk actions).

Kinds and states

Hover and focus are held in place. A box or dot hovered turns its edge to the “on” colour; a checked one doesn't change. Focus is the system's one ring, 2px off the edge (D8).

Every state, held in place, is in the live specimen at the end of this page.

  • Checkbox: a 16px box with a 2px corner; checked, filled with a check in the reverse colour.
  • Mixed (some but not all): the checkbox filled with a dash. Used on a list's header checkbox (“Select all shown”) when some rows are selected. It's set from script (el.indeterminate = true), so it isn't drawn on this page.
  • Radio: a 16px circle; selected, a thicker ring around an 8px dot.
  • Toggle: a 44 × 24 track with a 20px square knob that slides to the end when on. It mirrors in right-to-left layouts.

One “on” colour

Checked boxes and selected dots share one colour, black in light and near white in dark, and a toggle that's on is black in light and Bolster's yellow in dark. The audited product used black, brand blue and a lighter blue depending on the class. Blue is kept for links, focus and selection in lists (D21).

Size and touch

Each input sits in a .choice label, so the whole label is the hit area and the drawn box can stay small. A label row is at least 24px tall, and 44px on a touch screen, without drawing anything bigger.

Usage

  • Never recolour a box, dot or track. A new state is added to the system.
  • A disabled option says why nearby, or in its label: “Copy the last job (coming soon)”.

Content

  • Labels in sentence case, saying what “on” means: “Show getting started in navigation”, not “Getting started”.
  • A group of radios or checkboxes has a legend that names the choice: “Template search mode”.
  • Keep labels to one line where you can. A long one wraps beside the box, never under it.

Accessibility

  • Native <input type="checkbox"> and type="radio", restyled with appearance: none: Space checks, arrow keys move between radios, forms send the value, screen readers announce the state. The first-draft prototype rebuilt them as buttons with script.
  • A toggle is a checkbox with role="switch", so it's read as on or off.
  • Group radios in a <fieldset> with a <legend>; one tab stop per group.
  • An input with no visible label (a row's checkbox in a table) takes an aria-label: “Select Garage drywall”.
  • The box's edge and the toggle's off track are 4.0:1 on white, past the 3:1 a control needs. Labels use the text colours; the controls' off colour is for edges only.
