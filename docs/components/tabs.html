Components

Tabs

Panels of one page, one at a time: a job's Overview, Estimate and Takeoff. Tabs change what's shown, never what's saved; the arrow keys move between them.

Stablecomponents/tabs.cssUpdated 2026-09-29

When to use

  • Use tabs to split one page into panels that hold different things about the same record, where people need one at a time: a job's Overview, Estimate and Takeoff.
  • Use a segmented control to show the same thing another way (Month, Week, Day), or to switch a mode (Segmented control).
  • Use filter chips or summary cards to narrow a list; tabs never stand in for a filter (Filter chip, Summary cards).
  • Use the app shell's navigation to go to another page (App shell).

Anatomy

  1. List. The tabs in a row on a hairline that runs the panel's width. Too many for the screen, it scrolls sideways.
  2. Selected marker. A 2px line in the primary ink under the selected tab, over the hairline. The selected label turns primary too.
  3. Tab. A button: its label, medium weight, in sentence case. An icon may lead it.
  4. Count (optional). A count badge after the label, for what's waiting in that panel (Badge).

Sizes

  • Default: 40px, 14px labels.
  • Medium (data-size="md"): 48px, 16px labels.

States

Hover and focus are held in place. Focus is the system's ring, drawn inside the tab so the list's edge doesn't clip it (D8).

Usage

Tabs change what's shown, not what's saved.

Content

  • One or two words, nouns, sentence case: “Overview”, “Estimate”, “Takeoff”.

Accessibility

  • role="tablist" with an aria-label; each tab role="tab" with aria-selected and aria-controls; each panel role="tabpanel" with aria-labelledby (I8).
  • One tab stop for the list: the selected tab has tabindex="0", the rest -1. ← and → move and select at once, Home and End jump to the ends, skipping disabled tabs. The script for this is about fifteen lines; the specimen has it.
  • The selected tab is marked by its line and its label's colour, not colour alone.
