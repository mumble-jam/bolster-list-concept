Floating bar

Bulk actions for the rows you've ticked: a dark capsule at the foot of the list with the count, three actions and More. On phones it takes the tab bar's place.

Stablecomponents/floating-bar.cssUpdated 2026-10-22

The floating bar appears as soon as one row is ticked and goes when the last is unticked. On desktop it floats over the foot of the list, so the rows stay where they are while you pick them. It says how many are ticked, offers the rest, and holds what can be done to all of them at once. The pattern around it, ticking and select mode, is in Bulk actions.

When to use

  • Use the floating bar on a list that has bulk actions, for actions on the ticked rows. Only where the list declares them: never invent bulk actions.
  • Use the record panel for one row's actions when it's open (Record panel), and the row's ··· menu otherwise (Popover).
  • Use the toolbar to narrow the list, not the floating bar (Toolbar).

Anatomy

  1. Count (.floating-bar-count). A chip with its own ×: pressing it clears the selection, as Escape does from anywhere in the page.
  2. Select all (.floating-bar-link). A quiet underlined link that names how many it would tick.
  3. Actions (.floating-bar-actions). Ghost buttons, 36 tall, each with the product's 14px icon beside its label. A menu (Change status) is one action with a chevron.
  4. More. The rest of the actions, Delete last in red after a rule.

The capsule is the inverse surface: near-black in light, light in dark. It's 48 tall with 6px padding and 14px corners, so the 8px corners of the buttons inside share their centre with it (D35). One rule follows Select all and one goes before Delete when Delete is on the bar.

Slots

A bar that showed every action turned into a second toolbar, so the actions get a fixed number of places, filled in the order the list declares them, most important first (D36).

WidthOn the bar
1100 and upThree actions, then More.
768 to 1099Two actions, then More. Labels stay.
Below 768Up to two actions, More, then Delete when the selection allows it, in the tab bar's four places. One action fewer while a label wouldn't fit its place.
  • More never holds a single action. If only one would be left over, the last slot goes into More with it.
  • Delete lives at the end of More. It comes out onto the bar, last and after a rule, only when every action fits without a More (several jobs: Change status, Archive, Delete).
  • So after the count and Select all, the bar has at most four buttons.
  • The actions follow the selection: one pending job offers more than several jobs of mixed statuses.

States

Everything ticked

Once every matching row is ticked, the count says “All 132 selected” and Select all goes: the chip's × already clears them all (D54). Focus moves to the chip.

Coming and going

It slides up 8px and fades in over 240ms, and leaves the way it came, keeping its contents until it's gone. With reduced motion it only fades. While a record is open beside the list, the bar sits over the list, not the record.

On phones

Selecting takes over the chrome. A page header shows the count (“Select jobs” before anything's ticked), Select all and Done; once that header has scrolled away, a compact bar with the same three takes the top bar's place (D39). At the bottom, the floating bar becomes the action bar in the chrome's own dark, where the tab bar was: each action an icon over its label, More, then Delete in red. Until something is ticked its actions are disabled. Done ends the mode and unticks everything (D34).

Try it in the live job list: tap Select, or hold a row (job list concept).

Usage

  • Red is for what can't be undone. Archive and Delete both confirm first, and the confirmation's final button is the only filled red (Dialog).
  • Keep the order the list declares; don't reorder actions by width.

Content

  • The count: “3 selected”; with everything: “All 132 selected”.
  • Select all names the total: “Select all 132”.
  • Actions are the list's own verbs, the same words as in the row's menu and the record: “Change status”, “Archive”, “Send now”.

Accessibility

  • The bar is role="toolbar", named with the count: “Bulk actions for 3 selected”.
  • The count chip is a button named “Clear selection (3 selected)”; its count is a live region, so a change is read out.
  • Escape clears the selection from anywhere in the page, unless a menu, a dialog or a text field takes it first.
  • While it's leaving, the bar is inert, so nothing in it can be reached.
  • Change status and More say they open menus (aria-haspopup="menu").
