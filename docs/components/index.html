Components

Every part Bolster's pages are built from, from a button to the app shell: what's stable, what's being tried out, and what's still to build.

Each built component is one CSS file in system/components/, with a page here and a specimen showing every variant and state. They're plain HTML and CSS: a class names the component, data attributes pick its variant, size and tone (.button[data-variant="secondary"][data-size="sm"]), and the platform does the behaviour where it can (<dialog>, popover, <details>). Any script a component needs is small and never required for it to look right.

  • Semantic tokens only. A component says --color-action-primary, never a primitive such as --color-blue-print-600, so light, dark and a change of palette reach it unchanged.
  • Low specificity. Selectors stay light, most wrapped in :where(), so a page can adjust a component without a fight.
  • Layers. Everything sits in @layer tokens, base, components, utilities, in that order, whatever order the files load in.
  • One import. system/bolster.css brings in all of it. See Getting started.
