Interaction contracts

How things behave: what triggers them, what moves, where focus goes, which keys work and how they close. Read straight from docs/interactions.md.

docs/interactions.mdUpdated 2026-11-02

An I-entry is a contract: components and pages implement it, and a change to the behaviour is a change to the entry first. Each one notes the behaviour it replaces in the live product.

I1Dialog (modal)

#
Triggera button; dialog.showModal()
Motionbackdrop fades in, panel scales 0.97 → 1 and fades, 240ms ease-out; reversed on close
Focusmoves to the first focusable element, or the one with autofocus (in a confirm, the safe choice: "Keep job"). Trapped inside while open. Returns to the trigger on close
KeyboardEscape closes. Tab cycles inside
DismissEscape, a close button (aria-label="Close"), or the footer's cancel. Backdrop click only where nothing can be lost (closedby="any")
Semantics<dialog> (implicit role="dialog", modal), aria-labelledby its heading; aria-describedby for confirms
Replacesfilter dialog (the best as-is overlay: kept role and label, adds Escape)

I2Picker sheet (long selects)

#
Triggera field-styled button showing the current value, with aria-haspopup="dialog"
Motiondesktop: as I1. Phones: slides up from the bottom, 240ms ease-out, with a drag handle
Focusthe search field inside. On close, back to the trigger, which now shows the chosen value
Keyboardtyping filters; arrow keys move within the radio list; Enter or "Done" confirms; Escape closes without changing the value
DismissEscape, backdrop click, "Done"
Semantics<dialog data-variant="sheet"> holding a labelled search field and a radio group. "Add a new type" sits in the footer, not above the options
Replacesthe as-is select sheet: no dialog role, Escape ignored, focus lost to <body>, "Create new" row above every option list

I3Menu

#
Triggera button with popovertarget and aria-haspopup="menu"; aria-expanded mirrors the state
Motionfades and drops 4px, 120ms ease-out
Positionbelow the trigger, aligned to its start edge; flips when there's no room (CSS anchor positioning). Browsers without it centre the menu
Focusthe first item on open; back to the trigger on close
KeyboardArrowUp and ArrowDown move, Home and End jump, Enter or Space activates, Escape closes
DismissEscape, click outside, choosing an item
Semanticsrole="menu" with menuitem / menuitemradio; destructive items last, after a separator
Replacescompany and avatar menus: correct role, but no aria-expanded on the trigger

I4Tooltip

#
Triggerpointer hover (150ms delay) or keyboard focus (instant) on the anchor
Motionfade, 120ms
Focusstays on the trigger
Keyboardshows on focus, hides on blur. Escape isn't needed: it never traps or covers
Semanticsrole="tooltip"; the trigger points at it with aria-labelledby (icon-only buttons) or aria-describedby
Rulesa short phrase, no period. Never the only place important information lives: there's no hover on touch
ReplacesPrimeVue tooltips not linked to their triggers, so icon buttons had no accessible name

I5Toast

#
Triggerthe result of an action the user just took
Motionrises 8px and fades in, 240ms
Focusnever moves focus
Timingsuccess and info leave after 5s, paused while hovered or focused. Errors stay until dismissed
Semanticsone aria-live="polite" region per page; errors use role="alert"
Placementbottom right; on phones full width above the bottom tab bar
Replacesan error toast that stayed on screen across route changes, with misspelled copy

I6Opening and selecting list rows

#
Openclick anywhere on the row, or Enter on the row's name link. A thing with its own full-screen window opens it (the job workspace, I7; a vendor's window); anything else peeks: the record beside the list, a side sheet below 1280 (D30, D69)
Quick lookwhere rows open a full window, the row's ··· menu starts with Open (named after it: “Open job”, the expand icon) and then Quick look, the record beside the list; the record's own More leaves both out
Selectthe checkbox in the first cell. Shift-click for ranges (to spec). The header checkbox selects all and shows mixed when partly selected
Bulk actionsthe floating bar appears once one row is ticked (D34): a count chip that clears (as does Escape), Select all (gone once everything is ticked: the chip clears it all, D54), then three slots and More (D36): the list's first actions, the rest in More (never just one), Delete at the end of More unless everything fits on the bar. Two slots from 768 to 1099 wide
Thumbnails (D55)in the name's slot, the photo draws over its placeholder, so the placeholder shows while it loads; a link that breaks takes the photo away and leaves the placeholder. On phones a list with photos shows them down the left of each item; a list with none drops the slot
Phones (D32, D34)no checkbox column. Select in the page header, or a long press on a row (it starts the mode with that row ticked; moving cancels it, so scrolls don't). The checkboxes slide in and a tap ticks instead of opening. The header shows the count with Select all and Done, and once it has scrolled away a compact bar with the same three takes the top bar's place, going and coming back with the bars and showing whenever a row is ticked (D39); the tab bar turns into the action bar (up to two actions, More, Delete; one action fewer while a label wouldn't fit: D36), disabled until something is ticked. Done ends the mode and unticks everything
KeyboardTab reaches each row's link and checkbox; Space toggles the checkbox
Replacesclick selects, double-click opens; rows unreachable by keyboard

I7Job workspace

#
Triggeropening a row (I6) or a job link
Motionas I1
URL?job=<id> while open, removed on close, so back and forward work and links can be shared
Focusthe workspace heading; back to the row link on close
KeyboardEscape closes unless a spreadsheet cell is being edited (Escape then cancels the edit first)
Semantics<dialog data-variant="workspace">, the close button labelled "Close job"
Replacesthe as-is job modal: unlabelled close button, and ?job= re-added across route changes

I8Segmented control, filter cards and tabs

#
Segmented control, filter cardsnative radio groups: one tab stop, arrow keys change the choice immediately
Tabsroving tabindex: arrow keys move and activate, Home and End jump. Panels are role="tabpanel" with aria-labelledby
Rulea segmented control changes a mode or view in place; tabs switch panels; filter cards filter the list below them, one card at a time: each applies its own filter (a status, a flag, a category value), pressing another replaces it, pressing it again or All clears it, and its chip reads as the card (D66)
Replacesfilter cards as plain buttons with no selected semantics; segmented labels going bold and shifting

I9Navigation at each width

#
≥1024one sidebar with every section (trying out, D88), its foot (Messages, Files, Help, Settings, folding; Help moved there from the top bar, D118) fixed while the rest scrolls; a section with pages is an accordion, a chevron at its row's end turning down as it opens (<details name>: one open at a time, the current page's open on arrival, opening another closes it); the pill marks the page you're on, or its section's row while the section's folded (D98). Dark, as the chrome. Folded to the icon rail by default (D115); opened, that's remembered in the browser. Collapse menu at the logo cell's end folds it to the icon rail (remembered, D92), the menu staying open over the page where it was until the pointer leaves; folded, the same button, Keep menu open, shows as the rail opens and pins it again
Rail, when the sidebar is hidden (D25)stays its own width (D107): pointing at a section with pages opens them in a popup beside it after 60ms (70ms in) (the section's name, its pages with icons, the page you're on in the pill), moving to the next section moves it there at once, pointing away from both (80ms), Escape or a choice closes it; a row without pages (and Expand menu) shows its name alone in the same popup, a label the pointer passes through; every popup's name is level with its row's icon. A section's row taking keyboard focus opens its popup; Tab or ArrowRight goes in, arrows move, Escape or ArrowLeft back to the row. Expand menu at the rail's foot pins the menu; Collapse menu at the menu's foot, under Settings, folds it. D98's menu over the page (widening to 256 on hover) stays only in the menu playground; its switch in the concept controls is gone (D122)
Settingsfrom the sidebar, the rail or the company menu: a full-screen window with its own navigation (groups, then pages); a built page opens in its right part as the page itself (D89), its header's fold button hiding and showing that navigation; Close or Escape closes it, focus back where it was
768–1023the phone's navigation (your call, 22 Oct): no rail and no top bar; the floating menu button, bottom left, opens the menu at the pinned menu's width (256), with search, Bolton and your account in it (Help in its foot, D118), pushing the page aside by as much; the pages' own layouts stay their desktop ones until 767
<768no tab bar and no top bar: a floating menu button (bottom left) opens the same sidebar, its rows 44 tall, which pushes the page aside to an 88px column (320ms); the button rides into that column as ✕, and a tap anywhere in the column, a link or Escape close it, the page sliding back. Search, help, Ask Bolton and your account are in the menu. While rows are ticked the button steps aside for the bulk bar
The top bar's search (D112)a field: ⌘K (Ctrl+K off a Mac) or / from anywhere focuses it, its words chosen; its end shows ⌘ K at rest, esc while focused, Clear once it holds words (Clear empties it and keeps focus); Escape empties it, a second Escape leaves it; Enter searches (in these concepts, a toast says it isn't wired up)
Replacesa sidebar that stayed open at 768

I10Global search

#
Triggerthe top bar's field: a click, ⌘K / Ctrl+K from anywhere, or "/" where the page has no search of its own (D112)
What opensa panel under the field, as wide as it (D119): type chips (All, Customers, Jobs, Invoices, Files, Tasks); before typing, the records you opened last; typing turns it into results grouped by type in that order, three each with See all n (the type's list, searched), the typed letters marked, then the words themselves as a row. Nothing is created from it (D123). A word matches a name, an address, an invoice number or phone number's digits; every word must match
Narrowinga type chip narrows it (eight rows) and shows in the field as a token with ×; Backspace at the field's start or Escape on an empty field widens it again; nothing found while narrowed offers the count everywhere
Focusstays in the field (a combobox); the arrows move through the options (aria-activedescendant), the first result in focus as you type; Enter opens the one in focus: a record opens its list searched for it (the concepts have no record pages yet), the words' row will open a results page (later, C)
DismissEscape empties the field, then closes it and leaves; Tab or a click outside closes it
Phonesno top bar: Search stays in the menu (your call, 23 Oct)
Replacesa full-screen blurred layer with no dialog role, focus lost to <body> on close; live Bolster's dialog with eight type chips all on (narrowing meant removing seven)

I11Focus return, in general

#

Whatever opened an overlay gets focus back when it closes. If that element is gone (the row was archived), focus goes to the list's heading. Never to <body>.

I12Busy buttons

#

While an action runs, the button shows a spinner and a progressive label ("Saving…"), sets aria-busy="true" and ignores clicks. It stays enabled for screen readers, so they don't lose their place.

I13Live areas keep their shape

#

Anything on screen that updates while the user acts elsewhere (filters, search, sort, selection, paging) changes its values, never its layout. Every state, including full, few, none, loading and error, fills the same slots at the same size. A state is said by what a slot holds ("2 of 4", "None decided yet", an empty bar), never by adding or removing lines.

Statesdesigned in one frame: they overlay exactly, apart from the values
Sizescome from the data, not from what's on screen: numbers use tabular figures, and every column but the first is measured, never guessed: as wide as the widest thing it can ever show (each value across the whole list, every status in its status map even if no row has it yet, its header with the sort arrow). A hand-set width is only a floor; only the first column truncates. Sorting, loading more or a new status can't resize or clip anything
Optional partsleave a placeholder: a bar becomes an empty track, a figure becomes a word. Nothing disappears
Things that come and goappear where the user acted and push only what's below it, or float over the page (the bulk bar, the side panel)
The readeris never moved: a redraw keeps the scroll position and focus (focus({ preventScroll: true }) on anything sticky), and content shrinking doesn't pull the page out from under the pointer
Replacesthe data list concept's first passes: columns sized by the rows on screen (sorting resized them), then hand-set column widths (adding "In progress" clipped its badge), focus on a redrawn sticky header (sorting scrolled the page), and an insight card that swapped its bar for a caption line as filters changed
Still openin the concept: the chips row pushes the table down when the first filter is added; filtering to nothing collapses the table under the pointer

I14Picking dates

#

The calendar and the date range picker (D37), after the WAI-ARIA date picker pattern.

Openingthe date button opens the picker under it, focus on the pressed preset; on phones a bottom sheet of presets, Custom… drilling in
Presetsa click or Enter applies and closes; ↑ ↓ Home End move between them
Daysthe first pick starts a span, the second ends it (an earlier day swaps them); while half built, the band follows the pointer or the focus
Calendar keys← → a day, ↑ ↓ a week, Home End the week's ends, Page Up Down a month (with Shift, a year); the months follow; one tab stop, on the focus day
TypingFrom and To read Sep 8, 2026 · 8 Sep 2026 · Sep 8 · 9/8/2026 · 2026-09-08 on Enter or leaving the field; the month then shows. A date that isn't one, or comes after today for a past date, is flagged in the foot and Apply waits
Committinga hand-built span waits for Apply; Cancel, Escape or a click outside leave the filter as it was, focus back on the button
Reading backthe button names the date and the span: "Created · Sep 8 – Oct 3, 2026"; a span that matches a preset reads as the preset

I15Nested menus

#

A menu row with items of its own (a setting in Display settings, Change status, Download) reads its value and opens a second menu. On phones every menu is a bottom sheet with no room beside it, so the row drills in instead. Defined once, in the shell (BolsterShell.nestedMenus, D126): the lists and the pipeline use it.

Opening (desktop)beside the menu, on the side with room, its first item level with its row; below the row when there's no room on either side. A click opens it; a mouse resting on the row opens it (120ms), on a row without one closes it (200ms)
KeysArrowRight, Enter or Space on the row go in, focus on the checked item or the first; ArrowLeft or Escape come back out, focus on the row. ArrowUp, ArrowDown, Home and End move between a menu's items, skipping disabled and hidden ones
Drilling in (phones)the row's items replace the sheet's rows (every other row goes), the sheet easing to its new height; focus on the checked item or the first
The way backa header on top: Back on the left, the menu's name in the middle, a rule below; the whole row taps back (or ArrowLeft), and focus returns to the row you came from
Leavinga pick acts and closes the sheet; a tap outside or Escape closes it from any level

I16Money bar figures

Superseded#

Dropped with the money bar: KPIs are summary cards (I8). Kept as a record. A list whose KPIs were a money bar (D67) filtered from its figures, as summary cards do.

Pickinga figure (Overdue, Not due yet, Paid in the last 30 days) or the note under the bar (drafts) applies its filter; one at a time, pressing another replaces it, pressing it again or clearing its chip goes back to everything
Chipsthe chip reads as the figure: “Status: Overdue”, “Paid: Last 30 days” (a window is a filter of its own, kept out of the Add filter menu)
Countingthe figures follow the list's other filters; a window (the last 30 days) doesn't follow the date range, and says so
The bara picture of the figures, hidden from screen readers; never a target

I17To-do rows

#

A to-do list (D72) works on its rows in place; nothing asks first, and what changes stays where it was until the list is next drawn.

Completingthe round check, a real checkbox named “Complete …”; one click or Space ticks it. The task is struck through where it is, the group's count drops, and a toast says “Task completed” with Undo (5 s). Unticking reopens it the same way
Where done goesit stays in its group until the list is next drawn (a search, a filter, the other grouping), then it's in Completed, the last group, folded; its header opens it
Setting a fieldthe due date and the assignees are chips, priority the bars in the columns before the hours (D114); each opens a menu (a sheet on phones) and saves on pick; the assignees' one ticks people on and off as you go and stays open, the row moving to its new group if the date changed. Focus goes back to the chip. Empty chips (and no priority, as empty bars) show on hover and focus only
AddingAdd task at the end of a group opens a field there: Enter adds the task with the group's value (its day, its job) and keeps the field for the next; Escape, or leaving it empty, closes it. Create task opens it under Today
Reorderingdrag a row by its handle (shown on hover); on phones, where there's no handle, a long press (450 ms, a tick of vibration where there is one) lifts the row, the finger moves it, the page scrolls near its edges, and letting go drops it; moving sooner is a scroll, and the press doesn't open the task. From the keyboard, focus the handle and press Alt and ↑ or ↓, the new place read out. While dragging, a line in the seam between two rows (from the check to the row's end, a dot at its start) shows where it lands; never a row's own edge, whose rounded corners read as picking that row. Within a group it only reorders
Moving to another daygrouped by when, a drop into another day's group (on a row, its header or its Add task), or Alt and an arrow past a group's edge, gives the task that day: Today and Tomorrow exactly, This week and Later their first day unless its date is in them already, No due date none. A toast names the new date, with Undo. Overdue and Completed take no drops; grouped by job, a task stays in its job
SelectingSelect in the header turns every check into the system's square box; a tap on a row ticks it; the floating bar offers Complete, Due date and Assign. Done ends it
Openingthe title opens the task: beside the list from 1280 wide, a sheet below; its fields set the same way; Close, or Escape on the sheet, returns focus to the title

I19Loading screen

#
Whenthe first page of a session, over everything (D90); in the prototype from the concept controls too
What showsone of Anna's 16 drawings at random (not the last one), a line from its trade under it, changing every 2 s or so (Anna's three dots after it)
Donethe drawing finishes (a tape snaps shut, a scene settles), her done line for a beat, then the screen fades (260 ms)

I18Calendar

#

The calendar (D75) works on its items in place: a click opens a summary, a drag moves, and every change says so in a toast with Undo.

Openinga click (Enter, Space) on a bar, an appointment or busy time opens its summary in a popover over the grid, a sheet on phones; focus goes to its title (its ring only when it was opened from the keyboard); Close (× in its corner, as on every popover the calendar opens), Escape or a click outside closes it and returns focus to what opened it. A bar's later copies open the same summary
Picking what's shownShow and People each open a picker under their button, named with what it picks (“Show: Everything”); Show's kinds (job work, sales appointments, events, other calendars) each have their colour's swatch, the colours' key (D101); their options tick on and off and it stays open; Escape, Close or a click outside leave it, focus back on the button. The view is the segmented control beside them
A full day“+n more” (named “n more on Tue 13 Oct”) opens the day's list in the popover; a click on one of its items opens that item's summary in its place In Week and Day the all-day row is always two lanes: a day with more shows its first and “+n more”, so the hours never move between pages (your call, 22 Oct).
Movingwith a mouse or pen, drag a bar or an appointment: a dark tag follows the pointer with where it would land (the days, the time, the person), the days it would cover light up, and letting go saves it, with a toast naming the new day and Undo. A bar keeps its length and the day you grabbed it by; in Week and Day an appointment snaps to 15 minutes; in Crew a drop on another row gives it to that person instead of who it was under. Escape while dragging cancels. Busy time from other calendars doesn't move. Touch scrolls, as always: phones move things in the summary
Stretchingdrag a bar's end (it shows on hover) to change its last day; it can't end before it starts
Moving by keyboardthe summary's Starts (a bar), or Day and Starts (an appointment), then Move; same toast and Undo
SchedulingUnscheduled (an icon button after the rule, named with its count: “Unscheduled, 3 jobs”) shows a tray beside the calendar (from 1024 wide; open the first time, then as it was last left, in the browser) or a sheet (never on its own): drag a job onto a day, or open it, pick Start on, and Schedule. It leaves the tray, with Undo Its first-time default is open from 1280 wide and closed below (your call, 22 Oct); once you open or close it, that's kept.
Addingin Week and Day, a click on empty time makes a draft at that half hour, the company's default length (assumed an hour), and a drag over the hours draws its start and end, 15 minutes at a time; in Month and Crew a click on a day's empty space (a + shows on hover) makes one on that day at the next half hour (Bolster's default), in Crew for that person; the all-day row makes an all-day event. The draft shows on the calendar in the accent, “(No title)” until it has one, and a card opens beside it (a sheet on phones), focus in its first field
The cardSales appointment or Event (two tabs; it remembers the last one made). Rows led by an icon; controls read as text until pointed at. Time is a sentence: the date opens the browser's picker, start and end are lists in 15-minute steps (the end saying the length; a new start keeps it). An event: its title (typed, it shows on the draft), the date, start – end, All day, a location. A sales appointment: the customer, the date and start (its length is the type's), the type and who it's with; when that person is busy or off then, a line says so and Schedule reads Book anyway. Changing the date or time moves the draft. Enter or Save makes it; More options takes what's typed to the whole dialog; Escape, × or a click outside throws the draft away
The dialogCreate event in the header, More options, or the c key (outside a field) open it. An event: title; date, start, end, All day; whose calendar it's on (Busy · Default visibility · Notify 30 minutes before); guests as chips (a team member or customer by name, or an email address; Enter adds one, Backspace takes the last off, × removes one); location; description. A sales appointment: customer (or Create new customer), appointment type, who it's with, the date and that person's available half hours in their work hours (the busy ones struck, chosen with Book anyway), the site visit's address (the customer's, to change), notes. Save or Schedule appointment; what's missing is said under the form (“Choose a customer for the sales appointment.”). Cancel or Escape throws it away
Madeit shows on its day in the view you're in, with a toast naming it and Undo; it opens, moves and stretches like the rest
EditingEdit (a pen) in an event's or appointment's summary opens the dialog filled in, its kind fixed; the event stays put until Save, which changes it in place, with a toast and Undo; Cancel or Escape leaves it as it was
DeletingDelete (a bin) in the summary, Delete at the dialog's start, or the Delete key while a summary is open: gone at once, with a toast and Undo. Jobs' phases and busy time have neither: they change where they come from
Scrollingthe page scrolls, never the card (D128): Month's weeks and Crew's people share the screen's height, Week and Day's hours stretch to it, each at its least (an hour 3rem tall), past that the page scrolls; in Week and Day the weekdays and the all-day row stay at the top, under the top bar while it's there
Phonesa week strip over the week's agenda, and once it's scrolled away, the week as a short header at the top: a day in either scrolls to it, the arrows move a week, Today comes back; it opens at today

I20Pipeline

#

The pipeline (D94) moves leads and jobs through their stages on the board: a card's next step is on it, a drag moves it, a drop that needs something asks first, and every change says so in a toast with Undo.

AddingAdd, in the header (on phones, the floating +), opens a menu: Lead (a person, no job yet) or Job (Bolster's Create job, an empty estimate). Arrow keys move in it; Escape closes it, focus back on Add
Openinga click (Enter, Space) on a job's card opens the job (D104; the concept says it has no job window); on a lead's or an invoice's, its summary. A job's summary is Quick look, the icon at the card's top right (on hover or focus, always on touch). The summary opens in a popover beside the card, a sheet on phones: its stage and group, the full line about time (red when stuck), client or what they asked for, money, where, owner; Move to, its steps, Open job (or lead), Mark as lost. Close, Escape or a click outside return focus to what opened it
The next stepthe next step on a card (a link, an icon or a strip, by the card layout) does the stage's next thing: some at once (Send estimate, Mark as started, Record payment, with Undo), some in a short dialog (Create job, Book visit, Mark as booked, Schedule, Invoice) whose Cancel or Escape leaves everything as it was
Movingwith a mouse or pen, drag a card: a dark tag follows the pointer and says what the drop would do (“Create its job, in Pending”, “Mark as booked: contract and start”) or why it can't (“One stage at a time: Booked first”); stages it can go to are dashed, the one under the pointer lit, the rest faded. A card goes one stage either way; a person goes to Pending only by having its job created, and a job to Getting paid only by having its invoice created (from In progress). Invoices don't move by dragging. Letting go moves it, or opens the stage's dialog. Escape while dragging cancels; near the board's edges it scrolls. Order within a group is the date's, so there is nothing to drop between: a slot the card's size opens where it will land, the cards easing apart for it, dashed in the accent's blue on the card's ground (D121; it was a drop line, D104), in the group the drop puts it in at its date's place (under the head of a folded one), none where it can't go. While held, the card's place stays as a dashed outline, its contents faded, and the carried card lifts under the pointer; after any move, the card in its new place shows a brief accent ring and keeps focus (your call, 22 Oct).
Crossing kindsCreate job turns a person into a job (the person leaves Leads or Appointments); Create invoice makes an invoice of a job in progress: the final one from Work done (the job leaves the board), a progress one while it's underway (the job stays). Both ask first, both have Undo
Losinga lead, an appointment or a pending job dropped on Lost (its column while it's shown, Mark as lost at the foot while it isn't), or Mark as lost in the summary, asks why (one of five reasons) and the card goes to Lost, the board's last column, hidden until Display settings' Columns brings it in. There, Reopen (its next step, a drag back onto the stage it left, or Move to in its summary) puts it back where it was, with Undo
Moving by keyboardthe summary's Move to (only the stages the card can go to), then Move: the same dialogs, toast and Undo
A column's listpointing at a column's head (or tabbing into it) puts View in list in the place of its stage's mark, before its name: the stage's records in the table, filtered to it (Leads and Appointments the customers' Lead, the job stages their status, Getting paid the invoices, Lost the declined jobs) (D117)
Groupsa group's name folds and unfolds it, with its count and how many are stuck; folded groups are remembered in the browser
FindingAdd filter (an icon) opens People (whose) at once; once set it's a chip below, which reopens its picker, × removes it, Clear all, focus back on Add filter. Search is a button that opens into a field (Escape empties and closes it): name, client, address, job, invoice number, what they asked for. Both narrow every column at once, Lost too; the columns' counts and money follow, and the toolbar's count reads “4 of 29 cards” (the shown columns' cards)
Display settingsthe icon after the search opens a menu (a sheet on phones), each row a setting with its value that opens a nested menu: Columns (check stages and Lost to show; the last can't go), Column totals, Card size, Card details, Group by (Status, Owner, None); then Fold all groups and Unfold all groups, which leave it open. Arrows move, ArrowRight (Enter) goes into a nested menu, Escape or ArrowLeft comes back out, Escape again closes it, focus back on the icon. Every setting is remembered in the browser (D105)
Scrollingthe page scrolls down, the board sideways (a wheel's sideways motion, a trackpad, the scrollbar at the window's foot from 768 while the board's wider than the screen, or a drag near its edge). The page header scrolls away; the toolbar goes as you scroll down and comes back as you scroll up, or when focus goes into it; each column's head stays at the top of its column's part of the screen, under the toolbar while it's there
Phonesone stage at a time: tabs with counts (Lost's only while it's shown) at the top (they stay as the page scrolls), a swipe or a tab moves between stages; no dragging, Move to in the summary sheet

I21Timeline

#

The timeline (D97) moves stages in place: a click opens a summary, a drag moves, stretches or links, and every change says so in a toast with Undo.

Readingeach job a group, its row the list's group row (the group ground across), sticking under the scale while you're in its rows until the next job's pushes it away; a job's or phase's bracket, hovered, outlines its rows with a dashed line; the page scrolls it down, the scale sticking under the top bar (both slide up as it hides); along the days the chart moves itself: a trackpad's swipe, a tilted wheel or Shift and the wheel over it, a finger on a tablet, or its scrollbar pinned to the window's foot (D127); the names, starts and lengths stay at the left. A job's or phase's chevron folds it; a stage's opens its labor and materials. Every fact on a bar is in its row; a stage's name says its dates, working days and, when broken, that it starts too early
Moving alongToday puts today a quarter of the way in; the arrows move by most of a screen; the period says what's in view. Weeks, Months, Quarters and Fit change how far in; the choice is remembered in the browser Changing the scale keeps the day in the middle of the view where it is (your call, 22 Oct).
Openinga click (Enter, Space) on a stage's name or bar opens its summary at the bar, a sheet on phones; a job's name opens the job's. Close, Escape or a click outside return focus to what opened it
Movingwith a mouse or pen: drag a stage's bar to move it, its end to stretch it, a job's or phase's bracket to move all of it, a day at a time; a dark tag follows the pointer with the dates and working days; near the chart's edges it scrolls. Letting go saves it, with a toast and Undo; what waits on it moves by as much when it went later (named in the toast). Escape while dragging cancels
Linkingdrag from the small circle at a bar's end onto another stage of the same job: that stage now waits for it; a broken link is red and dashed. A stage of another job, or one that would make a circle, is refused with a toast. The summary's Waits for has × to remove it
Moving by keyboardthe summary's Starts, then Move: the same as a drag, toast and Undo
Showingthe filter button's Show ticks finished jobs (on by default, muted, left of today) and links between stages (on by default) at once; what's hidden is a chip, Hiding, its × showing everything (D127); Unscheduled (an icon, its count in its name) and Schedule a job list the jobs with no dates: open one, pick Start on, Schedule
Narrowingthe filter button opens a menu: Show, then Filter by, Jobs first (D127). Jobs opens a list with Find focused: typing narrows it by job or client; ticking a job shows only the ticked ones, at once; Clear in its head shows all again. Add filter opens a menu of the filters not set; picking one opens its options, each ticked at once with how many it would show. A set filter, Jobs included, is a chip (its name and values; a click changes it, × removes it), the count before them and Clear all after, which brings everything back. A stage's filters keep its job and phase rows; nothing matching shows an empty state with Clear all filters. Kept in the browser (D99)
Phonesa list: each job a card with its phases and stages, dates, what each waits for and a track of where it falls in the job; a tap opens the summary as a sheet; no dragging. Today and the arrows aren't there; the period is the plan's

I23Page scrolling

#

Every page scrolls the same way (D128, the rule); the shell's chrome hides and comes back as it does (D73).

Downthe page scrolls, never a card, a column or a part of one: what's longer than the screen makes the page longer. A tall part stretches to the screen when it's shorter than it (the calendar) and grows past it when it isn't
What staysheaders stick to the page, not to a card: the table's column header, the timeline's scale and its job rows, the calendar's weekdays, the pipeline's column heads. They sit under the top bar (and the page's toolbar, where it has one) and slide up with it when it hides
Alonga part wider than the screen (a table, the board, the timeline's days) scrolls sideways on its own: a trackpad's swipe, a tilted wheel, Shift and the wheel, a finger, or its scrollbar. Where the scrollbar is follows where the part sits (D141): on the page itself (the board), pinned to the window's foot, drawn so it shows on a Mac too; in a card (a list's table), the card's own, at its end; the timeline, in a card but moved through mostly sideways, keeps the foot one. The page itself never scrolls sideways
Not covereda popover, a menu, a sheet, a dialog and a side panel (the record, Your work) scroll inside themselves: they float over the page, so the page can't carry them

I22Motion (proposed)

#

How the system's motion behaves, from the motion research (D124, trying out). The lab's playgrounds implement it.

InterruptibleA motion turned around halfway (a dialog closed while opening, a section clicked twice) goes back from where it is, never from its end; a new change to a list moves rows on from where they are
FocusNever waits for motion: it's in a dialog, a menu or a sheet the moment it opens; the keyboard moves at once (arrowing through tabs doesn't queue behind the indicator)
Arriving and leavingLeaving is quicker than arriving (medium 250 in, 150 out); things arrive decelerating (--ease-enter) and leave accelerating (--ease-exit); on-screen moves use --ease-move
Where fromMenus and popovers grow from the corner at their button, from 0.96, never from 0; sheets from the bottom; content slides only the way someone went
WaitsA tooltip waits 300 ms, then for 300 ms after one hides the next shows at once, without motion; keyboard focus shows it at once. A loader shows after 300 ms and stays at least 300. A toast stays 5 s, 10 with an action, paused while pointed at or focused; errors stay
By handA dragged card or sheet follows the pointer 1:1; a sheet closes past 25% of its height or a flick over 0.4 px/ms, keeping the flick's speed, else springs back; Escape puts a dragged card back
Reduced motionWith prefers-reduced-motion: reduce: no translation, scaling, tilting, blur or loops; fades and colour changes stay (at most 150 ms); what a hand moves still moves
Never animatedFocus rings; anything started from a keyboard shortcut
ReplacesD10's global switch-off for reduced motion, and transitions that run the same curve both ways

I24Intent lens (trying out)

#

An inspector for how intentional the design is (D131), on concept pages that carry a record of it.

SwitchingConcept controls' Intent lens switch, or I (outside a field); remembered in the browser. Its bar's ×, or Esc with nothing pinned, turns it off. A toast says which
While onthe page doesn't act on a press, a click or a drag: they inspect instead. Hovering still shows what hovering shows (a card's Quick look), and the keyboard still moves through the page
Inspectingpointing at a part (or focusing it) outlines it in its level's colour with its name in a tag, and opens its card beside it (a sheet above the bar on phones): the level, the name, its status and element, your input, my part, from Bolster, still open, its decisions. The narrowest part with a record wins; a page's own before the shell's
Pinninga click pins the card (it stays while you point elsewhere, and its decision links open the documentation); a click on the same part, its Unpin, or Esc unpins; focus goes to Unpin when pinned and back to the part after
Paintingthe bar lists the levels with how many of the page's showing parts each has; pressing one outlines every part of that level at once (the finest parts, not what holds them), pressing it again clears them. The outlines follow the page as it scrolls and redraws

I25Forms (trying out)

#

How a form checks, says what's wrong, saves and asks before losing work (D134; system/components/form.js). With direction C (D140) it governs the fields that remain: creates, settings and a value's editor; how a record or a document saves follows its state, and waits for the C research.

CheckingNothing is checked on a form nobody has typed in. A field is checked when it's left after a change; once it's in error it's checked again as you type, and the error clears the moment the value is right. Choices (radios, checkboxes) are checked when one is picked. Pressing Save checks everything
ErrorsWords under the field, with an icon, in the label's words ("Enter company name", "Enter an email address like name@example.com"); the field is aria-invalid and tied to its message by aria-describedby. Everything typed stays
The summaryOn a failed save with two or more errors, or one out of sight: a summary at the top of the form ("2 things to fix before saving") with a link to each field; focus goes to it. A link puts focus on its field. Fixing a field takes it off the summary; the summary goes when nothing's left. With one error in sight, focus goes to that field instead
SaveOne way everywhere: changes are kept until Save. Never disabled to say what's missing. While saving it's busy (aria-busy, "Saving…") and ignores more presses; a failure keeps everything and says so
Where Save isA dialog's footer; a side sheet's foot; on a page, actions that stay at the window's foot while the form is on screen, with a note counting what isn't saved yet ("2 unsaved changes", announced politely), which says Saved once it is
SettingsSaved by their section's Save, switches included
LeavingWith unsaved changes, Cancel, closing or leaving asks once in a dialog: Keep editing (the default), Discard, Save. Nothing changed, nothing asked. Leaving the page itself (a reload, closing the tab) gets the browser's own prompt
Not covered yetMarks for values read from a source or suggested; forms built from the model; offline

I26Combobox (trying out)

#

Finding a value in a long list by typing, in the field (D138; system/components/combobox.js).

OpeningA click on the field, typing, or ↓. With nothing typed, the whole list (the pick ticked); from a server, nothing until something's typed
TypingThe list narrows at once (from a server: "Searching …" after 150 ms); the first row is ready for Enter (filled, as a pointed-at row is); the typed letters are marked where they matched, in the detail line only when the name didn't match; the count is announced politely ("12 clients, or add client")
Keys↑ and ↓ move through the rows, round the end, from wherever the highlight is; one row is highlighted at a time, moved by the keys or the pointer alike, and moved by the keys it carries the focus ring, as a menu's rows do; Enter picks the active row; Escape closes the list and puts back what was there (a second Escape is the dialog's)
LeavingKeeps only a pick. A typed name that's an option is picked; where free text is allowed (free), what's typed stands; otherwise the field goes back to its pick, or empty
AddingWith no exact match, "Add new client “…”" last. It opens the create form with what was typed; saved, the new one is picked; cancelled, focus is back in the field
SeveralA pick adds a chip and keeps the list open; picking a ticked row takes it off; a chip's × or Backspace in the empty field removes one, announced ("Ana Okafor removed"). The field stays one line: chips that don't fit are counted ("+3", named in its tooltip and label), and the count opens the list, the picks first, in the chips' order. While it's open the rows hold their places, so a row ticked or unticked stays under the pointer, still highlighted
PhonesUnder 640 the field opens the picker sheet (I2): the find box focused on top, a pick closes it (several: Done); the keyboard doesn't come back up on the field
In a formThe visible field holds the name, a hidden input the id (several: ids joined by commas); a required one says "Enter client" when empty; Discard puts back the chips

I27What a field does with what's typed (trying out)

#

Formats and numbers (D136, D137; system/components/field.js).

TidyingWhen the field is left, never while it's typed: a phone becomes (555) 014-2290, a ZIP 78704-1234, a number 1,250.5, money 1,009.10. Only a right value is tidied; a wrong one stays as typed
ErrorsSaid in words by the form (I25), the format's own: "Enter a 10-digit phone number, like (555) 014-2290, or start with + and the country code", "Enter a 5-digit ZIP code, like 78704", "Enter a number, like 12.5", "Markup must be 100 or less"
Stepping↑ and ↓ in a number step it by its step (Shift: ten), held between its min and max; no − and + buttons
CountryThe nearest data-country decides phone, postal code and number grouping; the US when none

I28Loading

#

What a part does while its data is on the way (D142; system/components/loading.js).

Under 300 msNothing changes: no skeleton, no flicker
Past 300 msThe part shows its skeleton, in the content's shape and size, and is aria-busy; "Loading jobs" is announced once, politely. What's already known (a title, a toolbar, a record's name) is there from the start
When it arrivesThe content takes the skeleton's place, the layout unmoved; a skeleton that showed stays at least 300 ms
Past 10 s"Still loading jobs…" at the top of the part, as a status; the skeleton stays
If it failsThe error state takes the part's place, with Try again, which loads it again the same way
Reduced motionThe bars stop shimmering
WhereA page's first load (its cards and table), a record (what its row says shows at once; the rest as bars), more rows (skeleton rows at the end of the list, the error and Try again in its foot)
Not thisThe loading screen (D90) is for the app's first open only; an action's own wait is its button's ("Saving…")
